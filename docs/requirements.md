# 요구사항 정의서

메챠 파인더가 무엇을 해야 하고, 어디까지 만들지 정리한 문서입니다.
확정되지 않은 내용은 **7. 미결정 사항**에 모아 두고, 정해지면 이 문서와 [결정 기록](decisions.md)을 함께 갱신합니다.

## 1. 목표

이미지 속 숨은 캐릭터를 YOLO로 탐지하고, 탐지 결과를 바탕으로 "얼마나 잘 숨었는지"를 점수와 능력치로 보여준다.

## 2. 범위

| 구분 | 내용 |
|---|---|
| MVP (1차) | 클래스 1개, 자세 1개 고정, 박스 라벨, 탐지 + 점수 계산이 끝까지 동작 |
| 확장 (여유 시) | 배경·크기 다양화, 자세 추가, 윤곽선 표시(세그멘테이션), 모델 보조 라벨링(1차 모델로 초안 → 사람 검수), 다중 캐릭터 탐지와 개별 점수 |
| 제외 | 범용 모델만으로 하는 완전 자동 라벨링, 실시간 영상 스트리밍 |

## 3. 기능 요구사항

우선순위: **M**(필수) / **S**(권장) / **C**(여유 시)

| ID | 요구사항 | 우선순위 | 담당 |
|---|---|---|---|
| FR-01 | 사용자가 이미지를 입력할 수 있다 | M | UI |
| FR-02 | 모델이 이미지에서 캐릭터의 박스 좌표와 신뢰도를 반환한다 | M | 모델 |
| FR-03 | 탐지하지 못한 경우(미탐지)를 구분해 반환한다 | M | 모델 |
| FR-04 | 탐지 결과로 은폐 점수(0~100)를 계산한다 | M | 점수 |
| FR-05 | 점수 계산에 탐지 신뢰도와 찾는 데 걸린 시간을 반영한다 | M | 점수 |
| FR-06 | 미탐지 시 점수 규칙을 정의하고 적용한다 | M | 점수 |
| FR-07 | 결과 화면에 원본 이미지와 탐지 박스, 총점을 보여준다 | M | UI |
| FR-08 | 평가 기준별 코멘트를 보여준다 | S | 점수, UI |
| FR-09 | 능력치를 오각형/육각형 차트로 보여준다 | S | UI |
| FR-10 | 박스 대신 캐릭터 윤곽선을 표시한다 | C | 모델, UI |
| FR-11 | 학습된 모델로 새 이미지의 라벨 초안을 만들고 사람이 검수한다 | C | 모델 |
| FR-12 | 한 이미지의 여러 캐릭터를 탐지하고 캐릭터별 점수를 보여준다 | C | 모델, 점수, UI |

## 4. 비기능 요구사항

| ID | 요구사항 | 기준 |
|---|---|---|
| NFR-01 | 이미지 한 장의 탐지~점수 계산이 데모에서 답답하지 않을 것 | 목표 약 5초 이내 (측정 후 조정) |
| NFR-02 | 실습실 PC에서 환경을 다시 만들 수 있을 것 | `requirements.txt`와 체크리스트만으로 재현 |
| NFR-03 | 모듈이 서로 독립적으로 개발·테스트될 것 | 모듈 간 입출력 약속을 지켜 더미 데이터로 단독 실행 가능 |
| NFR-04 | 데이터와 모델 가중치는 저장소에 올리지 않을 것 | Drive 공유 폴더로만 공유 |

## 5. 데이터 요구사항

| 항목 | 내용 |
|---|---|
| 수집 | 유튜브 영상과 직접 플레이한 화면에서 프레임 추출 |
| 라벨 | 직접 라벨링, YOLO 형식(`class cx cy w h`, 0~1 정규화) |
| 1차 규모 | 약 60~100장, 클래스 1개, 자세 1개 |
| 분할 | train 80% / val 20%, 같은 영상의 프레임이 양쪽에 섞이지 않게 영상 단위로 분할 |
| 보관 | Google Drive 공유 폴더 (원본 영상은 비공개) |

## 6. 제약 조건

- 개발 기간 이번 주 포함 총 4주, 3인 팀
- 실습실에서 매번 환경을 새로 설정해야 함
- 팀플 경험이 적은 팀원이 있어 Git 규칙을 단순하게 유지 (rebase·force push 금지)

## 7. 미결정 사항

| 항목 | 선택지 | 결정 시점 |
|---|---|---|
| "찾는 데 걸린 시간"의 측정 주체 | 사람이 화면에서 찾은 시간 / 모델 추론 시간 / 다른 방식 | 1주차 |
| 미탐지(탐지 실패) 시 점수 | 최고점 부여 / 별도 처리 | 1주차 |
| 능력치 축 구성과 개수 | 오각형(5축) / 육각형(6축), 축 이름 | 3주차 |
| 점수 공식과 가중치 | 신뢰도와 시간의 비율 등 | 3주차 |
| UI 구현 방식 | 웹 / 데스크톱 / 노트북 기반 등 | 1주차 |
| 윤곽선 표시 여부 | 세그멘테이션 전환 vs 박스 유지 | 3주차 |
| 외부 영상 사용 범위 | 공개 저장소에는 원본·프레임 비공개 유지 | 1주차 |

## 8. 완료 기준 (데모 시나리오)

1. 이미지 한 장을 입력한다.
2. 캐릭터가 박스와 신뢰도로 표시된다.
3. 총점과 기준별 코멘트가 나온다.
4. (권장) 능력치 차트가 함께 나온다.

위 1~3이 끝까지 동작하면 MVP 완료로 본다.
